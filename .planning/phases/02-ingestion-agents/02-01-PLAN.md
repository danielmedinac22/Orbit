**Part A: Upgrade settings.json hook (ASTR-08)**

Replace the entire `settings.json` content with this upgraded hook that uses imperative delegation language:

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write",
        "hooks": [
          {
            "type": "command",
            "command": "python3 -c \"import sys, json; d=json.load(sys.stdin); p=d.get('tool_input',{}).get('file_path',''); print('Orbit: Note written to .orbit/notes/. Delegate to the Astro agent now to assign themes, extract action items, log decisions, and rebuild the index.') if '.orbit/notes/' in p else None\" 2>/dev/null || true"
          }
        ]
      }
    ]
  }
}
```

Key differences from the Phase 1 placeholder:
1. The python3 one-liner uses `print(...)  if '.orbit/notes/' in p else None` — prints the delegation directive only when the path contains `.orbit/notes/`, and does nothing (None) otherwise. The old version used `exit(0)` logic with a separate `echo` that fired unconditionally after the python3 command.
2. The directive text is imperative: "Delegate to the Astro agent now to assign themes, extract action items, log decisions, and rebuild the index." — not the weak "Consider running Astro to organize."
3. `2>/dev/null || true` suppresses stderr (e.g., if stdin is empty or malformed) and ensures exit 0 always.

**Part B: Add navigator voice completion format to astro.md (BRND-01)**

In `astro.md`, replace the last line of the Rules section:
```
- When done, report a structured summary: notes processed, themes assigned, new suggestions, actions extracted
```

With a new section inserted AFTER the Rules section (before the end of the file). Add this complete section:

```markdown
## Completion Report

When done processing, report using this exact format:

```
Astro: Signal scan complete.
  N signals processed -> M constellations
  * Theme Name    -- N new signals, N missions extracted
  * Theme Name    -- N new signal
  Star chart updated.

  New constellation suggested:
  o Theme Name -- detected in N signals. Confirm?
```

When no new notes to process:
```
Astro: All signals already charted. Nothing new to organize.
```

**Vocabulary for reports:**
- Notes = signals
- Themes = constellations
- Action items = missions
- index.md = star chart
- Active themes use bullet prefix, suggested themes use "o" prefix

Replace N and M with actual counts. Only include the "New constellation suggested" block if there are actually suggested themes. Only include theme lines for themes that received new notes in this processing run.
```

Also remove the old summary line from the Rules section. The Rules section should end with:
```
- Suggested themes need user confirmation before becoming active directories
```

IMPORTANT: Use the exact Unicode characters from the branding spec for the completion report format. The bullet prefix for active themes is `●` (U+25CF BLACK CIRCLE) and suggested themes use `○` (U+25CB WHITE CIRCLE). The arrow in "N signals processed -> M constellations" is `→` (U+2192 RIGHTWARDS ARROW). So the actual format uses: `●`, `○`, `→`.
